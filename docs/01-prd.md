## 1. 产品概述

### 1.1 一句话定位

一个以「无限画布 + AI 对话」为核心的在线视觉创作 SaaS：用户在无限画布上通过自然语言对话生成、编辑、排列图片，完成多轮迭代创作；平台提供标准 SaaS 权限、额度管控与邮箱注册体系，后台可统一管理上游生图账号池与对话中转。

### 1.2 目标用户

| 用户类型 | 画像 | 核心诉求 |
|---------|------|---------|
| 普通用户 | 设计师 / 内容创作者 / 电商运营 / 市场同学 | 用一句话快速出图、反复修改、把成品排到画布上复用 |
| 超级管理员 | 平台运营 / 内部服务同学 | 看住号池健康度、控制额度发放、管理系统配置与用户 |

### 1.3 核心价值

1. **创作效率**：对话即创作，无需切工具、无需写 prompt 工程；一张无限画布承载从灵感到成品的全过程。
2. **可控成本**：积分制额度贯穿"发额度 → 用额度 → 看流水"，管理员随时刹得住。
3. **开箱即用**：邮箱注册 + 二次确认即开始创作，无需配置任何 Key；管理员在后台一键维护上游账号池。

## 4. 需求池（Requirement Pool）

> 优先级定义：**P0 = 必须（MVP 不可缺）** · **P1 = 重要（首版应含）** · **P2 = 可选（后续迭代）**
> 每条均含验收标准（可测试）。

### 4.1 P0 必须实现

| 编号 | 需求描述 | 验收标准 |
|------|---------|---------|
| P0-01 | 邮箱注册：邮箱+密码注册，密码需强度校验（≥8 位含字母数字） | 输入合法邮箱与合规密码可提交；邮箱格式错误/密码过弱给出行内错误提示 |
| P0-02 | 邮箱二次确认机制：注册后发送确认邮件，含带 token 的确认链接 | 注册成功后账号处于"待确认"状态且不可登录；点击有效确认链接后账号激活可登录 |

## 5. 功能详述（模块级）

> 供架构师拆解接口与数据模型使用。每模块含：关键对象/字段、行为规则、边界与异常。

### 5.1 认证与账号模块

**关键对象**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | uuid | 用户主键 |
| `email` | string(unique) | 登录账号，唯一，小写归一 |
| `password_hash` | string | 加盐哈希（bcrypt/argon2） |
| `role` | enum | `admin` / `user` |
| `status` | enum | `pending_verification` / `active` / `banned` |
| `display_name` | string | 昵称，默认取邮箱前缀 |
| `locale` | enum | `zh-CN` / `en` |
| `theme` | enum | `light` / `dark` / `system` |
| `created_at` / `last_login_at` | datetime | 时间戳 |

**行为规则**
- 注册：校验邮箱格式唯一 + 密码强度（≥8 位含字母数字）→ 创建 `pending_verification` → 生成一次性确认 token（24h）→ 发信。
- 确认：token 校验（有效 + 未过期 + 未使用）→ `status=active` → 写入初始赠送额度（200）+ 流水。
- 登录：`status=active` 才可登录；`pending_verification` 返回"请先确认邮箱"；`banned` 返回"账号已封禁"。
- 找回密码：发重置 token（1h）→ 重置后令牌失效全部会话。
- 会话：签发 JWT/Session，含 `user_id`/`role`/ 过期时间；支持登出与"登出全部设备"。

**边界与异常**
- 邮箱大小写与首尾空格归一化；重复注册返回统一文案（不泄露账号是否存在）。
- 确认/重置 token 一次性消费；重发受 60s 频率限制。
- 密码错误使用通用提示，避免枚举。

### 5.2 额度模块

**关键对象**

| 字段 | 类型 | 说明 |
|------|------|------|
| `user_id` | uuid | 归属用户 |
| `balance` | int | 当前余额（积分） |
| 流水 `id` | uuid | 流水主键 |
| 流水 `type` | enum | `grant` / `consume_image` / `consume_edit` / `consume_chat` / `admin_adjust` |
| 流水 `amount` | int | 正为增、负为减 |
| 流水 `status` | enum | `processing` / `success` / `refunded` |
| 流水 `ref_id` | string | 关联生成/编辑请求 id |
| 流水 `operator_id` | uuid | 管理员调整时的操作者 |
| 流水 `note` | string | 备注 |

**行为规则**
- 每次消耗走"预扣 → 成功确认 / 失败回滚"，余额与流水同事务。
- 余额查询 `GET /me/quota` 返回 `balance` + 阈值 + 单价表。
- 拦截判定：`balance < 本次预估消耗` → 拒绝（错误码 `QUOTA_INSUFFICIENT`）。
- 预警：`balance ≤ 总授予额的 20%`（可配置阈值）触发前端告警，不阻断。
- 管理员调整：增加/扣减/直接设置，均落流水 + 审计日志。

**边界与异常**
- 并发消耗需乐观锁/行锁防超扣；扣减不得使余额为负。
- 生成失败必须回滚预扣；回滚幂等（同一 ref_id 只回滚一次）。

### 5.3 项目与画布模块

**关键对象**：项目（`id`/`owner_id`/`name`/`created_at`/`updated_at`）、画布（`id`/`project_id`/`state`(JSON)/`thumbnail`）、画布元素（图片节点：`id`/`type`/`url`/`x`/`y`/`w`/`h`/`z`/`meta`）。

**行为规则**
- 新建项目自动创建默认画布；画布状态自动保存（防抖，如 2s）。
- 图片节点支持拖拽/缩放/框选/多选/层级调整/删除；支持从资产库或对话结果"加入画布"。
- 画布缩略图用于项目列表与 minimap。

**边界与异常**
- 越权访问他人画布返回 404/403。
- 保存冲突以最后写入为准，配合前端节流降低并发。

### 5.4 AI 对话与生图模块

**关键对象**：会话（`id`/`user_id`/`canvas_id`/`title`）、消息（`id`/`session_id`/`role`/`content`/`attachments`/`created_at`）、生成任务（`id`/`user_id`/`type`(generate/edit)/`prompt`/`params`/`status`/`result_urls`/`cost`）。

**行为规则（对接集成服务）**
- 对话请求 → 网关路由到 **sub2api**（`/v1/chat/completions` 或 `/v1/messages`），用于意图理解 / 提示词优化 / 纯文本回复。
- 生图/编辑请求 → 网关路由到 **chatgpt2api**（`POST /v1/images/generations`，模型 `gpt-image-2`），支持多图组图编辑。
- 长任务返回任务 id，前端轮询/流式获取进度（生成中/排队中/完成/失败）。
- 结果图片：落对象存储（或本地静态目录）→ 写入资产库 → 自动落画布。

**边界与异常**
- 上游超时/限流：向用户返回可读错误（"上游繁忙，请稍后重试"），不计费。
- 号池无可用账号时，网关降级返回明确提示，不扣额。

### 5.5 资产库模块

**关键对象**：资产（`id`/`owner_id`/`kind`(generated/uploaded)/`url`/`thumb_url`/`width`/`height`/`source_prompt`/`created_at`）。

**行为规则**：网格浏览（时间倒序）、大图预览、下载原图、复用回画布、按来源/时间筛选。

**边界与异常**：删除资产不删除已在画布中引用的节点（仅资产库移除）；上传限制类型与大小（如 ≤20MB、png/jpg/webp）。

### 5.6 管理后台模块

**用户管理**：列表（邮箱/昵称/角色/余额/状态/注册时间）、搜索、筛选、分页；操作：分配额度、封禁/解封、重置密码、重发确认邮件。
**额度分配**：模式（增加/扣减/直接设置）+ 数值 + 备注 → 落流水与审计日志。
**号池管理**（代理上游管理接口，五类导入、刷新、状态监控）：

| 能力 | 上游接口（chatgpt2api） | 后台 UI 行为 |
|------|------------------------|-------------|
| 列表 | `GET /api/accounts` | 表格展示（标识掩码/类型/状态/额度/最后刷新） |
| 批量导入 | `POST /api/accounts`（tokens 或 accounts 数组） | 弹窗选方式（token/session/codex-auth/account-json/oauth）+ 粘贴 → 回执成功/失败数 |
| 刷新额度/token | `POST /api/accounts/refresh` + 轮询 `/progress/{id}` | 一键刷新 + 进度条 |
| 重新登录 | `POST /api/accounts/re-login` + 轮询 | 异常账号"重新登录" |
| 状态变更 | `POST /api/accounts/update` | 启用/禁用/改额度/改代理 |
| 删除 | `DELETE /api/accounts` | 单/批量删除 |
| 导出 | `POST /api/accounts/export` | 导出 json/zip |

状态枚举：`normal` 正常 / `limited` 限流 / `abnormal` 异常 / `disabled` 禁用；后台以颜色徽章呈现并可筛选。
**系统配置**：sub2api 地址+Key、chatgpt2api 地址、注册开关、维护模式、额度单价、初始赠送、确认链接时效、号池自动刷新周期；敏感值掩码显示 + 连通性测试。
**邀请码 / 公告 / 操作日志**：见 P1-11 / P1-07 / P1-10。

### 5.7 集成与配置模块（网关）

- 网关统一收敛：鉴权、额度预检/扣减、路由转发、错误码归一、审计。
- 全部上游地址与 Key 走配置（环境变量 / 系统配置表），支持"本地 → 线上"切换，禁止硬编码。
- 统一错误码：`QUOTA_INSUFFICIENT` / `UNAUTHORIZED` / `FORBIDDEN` / `UPSTREAM_ERROR` / `POOL_UNAVAILABLE` / `VALIDATION_ERROR`。

## 6. 核心流程描述

### 6.1 注册 + 邮箱确认流程

1. 用户在 `/login`（注册 Tab）输入邮箱、密码、确认密码，勾选同意条款。
2. 前端校验格式与密码强度 → 提交 `POST /auth/register`。
3. 后端创建用户，`status = pending_verification`，生成确认 token（有效期 24h），发送确认邮件。
4. 前端展示"确认邮件已发送"态（含目标邮箱、重发按钮、倒计时）。
5. 用户点击邮件中的确认链接 → 前端路由 `/verify-email?token=xxx` → 调用 `POST /auth/verify-email`。
6. 后端校验 token 有效性与时效 → 用户 `status = active` → 返回成功。
7. 前端跳转登录页/自动登录，授予初始赠送额度（如 200 积分），写入额度流水。
8. 若 token 过期/无效 → 提示并提供"重发确认邮件"。

### 6.2 生图扣额流程

1. 用户在工作台对话框输入 prompt（或选中图片后输入编辑指令）→ 点击发送。
2. 前端调用 `GET /me/quota` 预检余额（或读本地缓存的余额）→ 余额不足则直接走 6.4 拦截。
3. 网关收到请求 → 校验会话与角色 → 二次校验余额 ≥ 本次预估消耗。
4. 网关预留/预扣积分（乐观预扣）→ 写入流水（类型=生图，状态=processing）。
5. 网关转发到 chatgpt2api 生图接口（`POST /v1/images/generations`，模型 gpt-image-2），流式/轮询回传进度。
6. 成功：确认扣额（流水状态→success），图片落到画布 + 资产库；返回剩余额度。
7. 失败：回滚预扣（流水状态→refunded），前端提示错误，不扣额。
8. 前端实时刷新顶部剩余额度。

### 6.3 额度耗尽拦截流程

1. 用户触发任一消耗操作（生图/对话）。
2. 后端校验：`余额 < 本次操作所需积分` → 拒绝，返回统一错误码（如 `QUOTA_INSUFFICIENT`）。
3. 前端：拦截操作、按钮置灰、弹出模态提示"额度不足，当前 X，本次需 Y，请联系管理员分配额度"。
4. 提示中提供"查看额度明细"入口（跳转额度中心）。
5. 若余额 > 0 但低于阈值 → 顶部显示黄色告警条（"额度即将用尽"），不阻断操作。

### 6.4 管理员分配额度流程

1. 管理员在 `/admin/users` 定位目标用户（搜索邮箱）。
2. 点击"分配额度"→ 弹窗选择模式（增加 / 扣减 / 直接设置）+ 输入数值 + 备注。
3. 提交 `POST /admin/users/{id}/quota`。
4. 后端校验操作者为管理员 → 更新用户余额 → 写入额度流水（含操作者、备注）。
5. 用户侧余额实时/下次拉取时同步，流水可见。
6. 记录审计日志（谁、何时、给谁、改了多少）。

## 8. 额度体系设计

### 8.1 单位与规则

- **单位**：积分（Credit），整数计，最小单位 1。
- **初始赠送**：新用户邮箱确认后赠送 **200 积分**。
- **扣减规则**：

| 操作 | 计费方式 | 建议单次消耗 | 说明 |
|------|---------|------------|------|
| 对话生成（新图） | 按次 | **10 积分 / 张** | 默认 gpt-image-2 标准质量 |
| 对话生成（高清） | 按次 | **16 积分 / 张** | 高质量/大尺寸 |
| 图片编辑（局部重绘/风格） | 按次 | **8 积分 / 次** | 基于已有图编辑 |
| 纯文本对话（不产图） | 按次 | **2 积分 / 次** | 意图澄清/提示词优化 |
| 图片上传 | 免费 | **0** | 本地资产导入 |

> 规则由配置驱动（管理员可在系统配置中调整单价），默认值如上。

### 8.2 额度生命周期

```
注册确认 → 赠送 200 → 使用中实时扣减 → 低于阈值(20%)告警 → 耗尽拦截 → 管理员补额 → 继续使用
```

### 8.3 额度不足 UI 表现

| 状态 | 触发条件 | UI 表现 |
|------|---------|---------|
| 正常 | 余额 > 20% | 顶栏徽章显示积分，常规样式 |
| 预警 | 0 < 余额 ≤ 20% 阈值 | 顶栏徽章转黄色 + 顶部细告警条"额度即将用尽" |
| 耗尽 | 余额 < 本次操作所需 | 生成/发送按钮禁用；点击弹模态"额度不足"；提供"查看明细/联系管理员" |

### 8.4 数据一致性要求

- 每次消耗必须落一条流水（含用户、类型、金额、状态、时间、关联对象）。
- 预扣 → 成功确认 / 失败回滚，保证不会出现"扣了没出图"或"出了图没扣分"。
- 余额变更与流水在同一事务内完成。

## 11. 异常场景与状态续接（增量需求 · v1.1）

> 背景：部署于**国内服务器（服务器内部已配置 VPN 访问外网）**，上游（sub2api / chatgpt2api）需经服务端 VPN 出网。网络延迟高、可能抖动，用户存在"生图时暂停 / 刷新 / 重复提交"等操作。本章定义这些异常场景的产品行为，要求：**状态一致、不重复生成、任务不丢失、资源不泄漏、用户侧无感、流程可续接**。
> 本章为增量，编号独立延续（US-U-22 起、P0-28 起、P1-13 起），不改动已验收章节。

### 11.1 用户故事增补

| # | 用户故事 |
|---|---------|
| US-U-22 | 作为创作者，我想在生图/对话进行中点击"暂停"，这样我能临时腾出注意力而不丢掉这轮创作。 |
| US-U-23 | 作为创作者，我想在暂停后选择"继续"，这样我能从暂停处接着把这张图做完。 |
| US-U-24 | 作为创作者，我想在暂停后选择"放弃"，这样我能取消这次生成且不被扣费。 |
| US-U-25 | 作为创作者，我想在生成过程中刷新页面后自动回到进行中的状态和进度，这样我不会以为任务丢了、也不用重新输入。 |
| US-U-26 | 作为创作者，如果生成完成时我已经离开或刷新了页面，我想下次进入时能看到"结果已就绪"的提示并找回这张图，这样我的成果不会丢。 |
| US-U-27 | 作为创作者，在高延迟下我不小心连续点了两次或反复刷新，我想最终只产生一个结果、只扣一次费，这样我不担心被重复扣费或出现重复图。 |
| US-U-28 | 作为创作者，面对高延迟我想看到明确的"排队中/生成中/网络较慢"反馈，这样我知道系统仍在工作而不是卡死了。 |
| US-U-29 | 作为创作者，当网络恢复后，我想进行中的任务能自动接着完成，这样我不用手动重来。 |

### 11.2 需求池增补

#### P0（续 P0-27）

| 编号 | 需求描述 | 验收标准 |
|------|---------|---------|
| P0-28 | **生成中暂停**：生图/对话任务进行中，支持用户点击"暂停" | 进行中任务显示"暂停"按钮；点击后 UI 在 1s 内切换为"已暂停"态（含进度保留）；暂停中的任务**不再继续消耗额度**；暂停态下提供"继续"与"放弃"两个操作 |
| P0-29 | **暂停后恢复 / 放弃** | "继续"可恢复该任务并从暂停处接着执行，最终产出结果正常落画布；若暂停期间上游任务已完成，"继续"或重进时**直接呈现结果、不重新生成、不重复扣费**；"放弃"立即结束任务，未消耗部分额度**回滚**（流水状态 refunded），画布不产生该结果 |
| P0-30 | **刷新续接（进行中）**：生成/对话进行中刷新页面 | 刷新后重新进入工作台，自动恢复该会话/画布与"进行中"任务的状态与进度（轮询服务端任务态），不产生新任务；任务完成后结果自动呈现并落画布 |
| P0-31 | **结果不丢失（已完成但已离开）**：任务完成时用户不在当前页（含暂停期间上游自行完成的情形） | 再次进入时以提示/未读标记告知"有 N 个生成结果已完成"，提供"查看/加入画布"入口；结果已持久化，不因离开/暂停/刷新丢失；该情形下不重复生成、不二次扣费 |
| P0-32 | **幂等防重（高频刷新/重复提交）**：高延迟下对同一操作连续点击或刷新 | 同一操作携带客户端幂等标识（如 request_id）；服务端对相同幂等标识**只创建 1 个任务、只扣 1 次费**；重复请求返回同一任务结果；用户侧不可感知且结果唯一 |
| P0-33 | **防资源浪费（异常中断任务终态与回收）** | 每个任务有明确终态（success/failed/cancelled/timeout）；异常中断（进程重启/上游失联）任务由后台在超时阈值内标记终态并回滚预扣；**用户可见表现：任务不会永远转圈**，超时后给出结果或明确失败态 |
| P0-34 | **任务超时提示** | 超过任务超时阈值（默认 180s，可配置）仍未完成，UI 展示"任务超时，已停止并退还额度"（如已扣额），提供"重试"入口 |
| P0-35 | **网络恢复自动续接** | 因网络中断导致的进行中任务，在网络恢复后前端自动重新拉取任务态；若服务端任务仍在执行则继续展示进度，若已结束则直接呈现结果，无需用户手动重来 |
| P0-36 | **VPN / 上游不可达的显式反馈** | 服务端 VPN 出网异常导致上游不可达时，返回统一错误 `UPSTREAM_ERROR`/`POOL_UNAVAILABLE`；用户侧提示"上游服务暂时不可用，请稍后重试"，**不扣额**，不产生垃圾任务 |

### 11.3 UI / 交互约定

| 场景 | 控件与表现 | 文案示例 |
|------|-----------|---------|
| 生成中 | 结果卡片显示进度 + "暂停"按钮 | 生成中… （可暂停） |
| 已暂停 | 渐变暂停底/灰化进度条，进度值保留；显示"继续""放弃" | 已暂停 · 进度 62% |
| 继续 | 回到生成中态，恢复进度 | 继续生成中… |
| 放弃 | 任务结束，卡片标记取消，额度回滚 | 已放弃，额度已退回 |
| 刷新续接 | 页面加载后恢复到进行中态（骨架 + 进度），无重复气泡 | 正在恢复创作进度… |
| 结果补投递 | 顶部提示条 + 结果卡片未读标记 | 你有 1 个生成结果已完成，点击查看 |
| 高延迟 | 进度区附加弱提示，不阻塞操作 | 网络较慢，正在努力加载… |
| 任务超时 | 卡片转失败态 + 重试按钮 | 任务超时，已停止并退还额度 · 重试 |
| 上游不可达 | Toast（danger）+ 不扣额 | 上游服务暂时不可用，请稍后重试 |
| 暂停期间上游已完成 | 恢复/重进时直接呈现结果，不重复生成、不二次扣费 | 任务已完成，点击查看结果 |

交互原则：
- **暂停/继续/取消**三态在同一结果卡片内切换，避免跳页；任何状态下按钮点击都有即时反馈（禁用 + loading）。
- **暂停期间若上游已完成**：恢复或重进时**直接呈现结果、不重复生成**（服务端巡检捕获并置 succeeded，结果留存），显式强化 P0-31「结果不丢失」。
- 刷新后**不新增消息气泡、不新增任务**，仅恢复既有任务视图。
- 所有长任务均有明确视觉"正在工作"信号（进度/文案/动画其一），杜绝无反馈的空白等待。

### 11.4 幂等性产品口径

- 用户侧**不可感知**幂等实现细节（不暴露 request_id 概念）；对用户表现为"怎么点/怎么刷都只有一个结果、只扣一次费"。
- 验收口径：
  1. 同一生成操作在 5s 内被重复提交 ≥5 次 → 服务端仅存在 **1 个任务**，额度仅扣 **1 次**。
  2. 生成进行中刷新页面 1–10 次 → 任务数不增加，进度连续。
  3. 任务失败/取消后再发起同内容操作 → 视为**新任务**（不受前次幂等标识影响），可正常生成。
- 幂等窗口：默认以"任务存活期 + 短宽限期"为幂等有效期（建议 5 分钟，可配置），过期后相同操作视为新任务。

### 11.5 状态一致性与资源约束（产品级要求）

| 维度 | 要求 |
|------|------|
| 状态一致 | 页面展示的任务状态以**服务端为准**；前端仅做乐观展示，刷新后以服务端态对齐 |
| 不重复生成 | 幂等标识 + 服务端去重，杜绝重复任务与重复扣费 |
| 任务不丢失 | 任务与结果持久化，刷新/离开/网络中断均可找回 |
| 资源不泄漏 | 异常中断任务有终态 + 预扣回滚 + 回收；暂停中的任务不占用上游生成配额 |
| 用户无感 | 恢复正常流程无需用户手动重建上下文；续接对用户表现为"接着用" |
| VPN 适配 | 上游出网统一由服务端 VPN 承担；出网异常必须显式降级提示且不扣额，不产生垃圾任务 |
