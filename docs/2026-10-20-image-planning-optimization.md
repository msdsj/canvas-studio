# 图片需求规划与画布优化

本次修改覆盖图片规划、账号分配、任务执行、对话过程展示与画布交互。

## 原有缺陷与处理

| 缺陷 | 当前行为 |
| --- | --- |
| 按关键词或选区数量推断产出，模型未真正读图 | 对话先调用多模态 LLM，提供原图像素、带实际编号的定位图及用户原话；模型生成独立任务清单 |
| 多处要求合并或漏发，固定并发限制裁掉产出 | 每项独立产出创建一个 `n=1` 任务；根据语义决定合并修改或分别输出，不按框数机械拆分 |
| 只看账号总数，不能保证任务分配到不同账号 | 网关原子预留整批不同账号；每个任务重试及模型回退仍使用自身账号 |
| 局部编辑可能改变未选中内容 | 使用实际矩形、套索或画笔掩码，把编辑结果合成回原始 RGBA 图片，选区外像素保持原样 |
| 抠图可能重绘主体、返回空白素材 | 使用模型返回的透明度保留原主体颜色，限制到实际选区并裁除透明边；无透明度或无有效主体则失败退款 |
| 独立创作任务可能丢掉参考图 | 每项任务携带 `use_reference`；需要参考时将原图继续传给图像执行端 |
| 扣费或派发中途失败，流式响应可能中断 | 整批预检余额、任务上限、独立账号容量；建任务失败退回已预扣费用，不启动半批任务，并返回可见失败结果 |
| 扩展参数覆盖已计价的数量、质量或编辑内容 | 受控执行参数统一归一化，扩展字段不能覆盖；旧版素材多版本的费用也按实际产出计算 |
| 确认冲突、退款后重试误用失败任务 | 两条确认链路均原子认领方案；退款任务释放原幂等键，重试完整重建批次 |
| 对话区只有最终大段文字 | 流式展示公开分析摘要、图片观察、用户约束、产出拆解、最终执行指令及真实任务状态 |
| 多任务同时完成只自动放入最后一张 | 逐任务去重、串行放入画布，并隔离会话切换后的旧结果 |
| 图片操作面板与预览占用空间过大 | 操作按钮 26 px、图片间距 28 px、70% 磨砂底色；缩略图 120×76 px，结果默认最长边 200 px |

## 执行契约

`intent_plan.py` 校验 LLM 产出的 `jobs`，不通过本地关键词推导替代模型。每项任务有完整提示词、产出类型、选区编号、动态能力 ID、参考图策略及保留约束；选区坐标和路径由服务端绑定到原始选择，禁止模型猜测坐标。

支持一张整图包含多处修改，也支持多张独立版本、透明素材与新图混合输出。有歧义时先展示模型生成的备选方案；选中方案使用同一任务契约，重复确认不重复扣费，并发确认通过原子状态变更隔离。

当前单次最多 12 项产出，超出时明确提示，不静默裁剪。默认每用户活动任务上限改为 12；初始化只迁移无人为修改的旧默认值 2，保留管理员明确设置的上限。

分析过程展示面向用户的公开摘要和依据，不展示模型私有思维链。模型、耗时、已接收输出字数和任务费用来自真实返回或任务记录；未取得 token usage 时不推算 token 数或算力数值。

## 账号池配置与边界

后端、网关和前端需要一起更新。网关新增 `/gw/pool/capacity`，后端以该接口提供的实际可调度容量预检，不能以远端账号列表数量代替。多图请求在容量未知、不支持独立路由或可用账号不足时整批拒绝。

本项目的本地通用 API Key 池支持独立账号路由，可通过现有账号池导入功能配置；每条凭据须对应独立账号额度，可按需设置 `base_url`。这些凭据保存在网关 `POOL_FILE` 指向的位置。该调度器适用于单网关进程；多进程部署需要共享租约存储，不能用多个进程各自的内存锁保证全局隔离。

现有外接 `chatgpt2api` 的 ChatGPT 登录凭据池由上游自行选账号，当前接口没有指定执行账号的能力。仅有该远端池时，本项目无法保证 N 项任务使用 N 个账号，因此多图需求会明确失败；需要配置可独立路由的本地账号池，或让上游增加指定账号的接口后再接入。单图仍兼容原先配置的图片服务。

真实规划任务禁止使用演示图片冒充生成成功。账号池被占用、上游失败、素材输出不符合契约等情况会按真实结果显示失败并退回图片额度；分析服务自身的调用费用由中转站计费。

当前环境不允许监听本地端口，浏览器也不能打开本地 file 页面，因此没有完成浏览器视觉验收；没有调用真实付费 LLM 或 GPT image2 做线上联调。[画布尺寸与视觉验证记录](../deliverables/qa/current-optimization/README.md)包含实际组件检查页及限制说明。
