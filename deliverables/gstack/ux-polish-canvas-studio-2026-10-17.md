## 1. 各成员核心结论

### 🔍 产品官（产品链路与状态机）

- **核心判断**：问题不在"功能少"，而在**反馈缺失**。生图是长耗时异步任务，但界面只给了三个值（0/30/100），用户无法判断"在跑"还是"死了"，于是重复点击——而重复点击又被错误的幂等键吞掉，形成"越急越没反应"的死循环。
- **关键建议**：把"提交 → 排队 → 生成 → 结果 → 落画布"每一步都变成**可见状态**；幂等键必须绑"一次用户动作"而不是"一个会话"；生图 prompt 必须进消息时间线，否则对话式创作叙事不成立。

### 🛡️ 安全卫士（用户不可见内容管控）

- **核心判断**：用户侧信息泄露不是单点，而是**一条完整透传链**：上游 raw body → `error_message` 落库 → 任务卡原样渲染。除此外还有三个更硬的暴露面：`/docs` 与 `/openapi.json` 线上可达、容器 8000/8100 直接对外、图片 URL 带内网端口与用户 UUID。
- **关键建议**：错误只允许以"枚举码 → 固定中文文案"的形式出前端，raw 详情一律进日志；生产环境关闭 docs/openapi 与端口发布；错误文案里禁止出现"上游/中转/网关/号池/代理/HTTP/状态码"。

### ✅ 质量门神（异常矩阵与验收）

- **核心判断**：31 个异常场景里有 10 个会直接毁掉一次创作，且多数**不是罕见路径**——弱网、连点、中文输入法选词回车、粘贴长文、上游 502，都是日常。当前前端**没有任何一处 `img onError`**，也没有请求超时。
- **关键建议**：先补"失败可见"（占位图、超时、原地重试），再补"失败可恢复"（网络恢复重试、迟到结果认领）。验收必须写成 Given/When/Then，其中错误文案要用正则断言不含技术词。

### 🎨 设计师（遮挡与视觉状态）

- **核心判断**：画布区域被三组"自己造的浮层"侵蚀——自建缩放条压在 Excalidraw 原生缩放岛上（按钮点不到）、编辑层工具条用魔数 `top-[88px]` 且窄屏折行侵入画布中心、toast 固定右上正好压住顶栏与画布头。此外 `queued` 与 `cancelled` 视觉完全相同，用户分不清"在排队"还是"已放弃"。
- **关键建议**：定义"零浮层区"（顶栏带、画布头带、画布上下 56px 岛带、输入框块、dock 列、画布中心 60%），任何浮层不得侵入；生成中的加载必须是**元素级骨架**，不许全屏遮罩盖住图片。

## 4. 交互规则（提交控制与输入）

> 写法约定：「当 X 时，必须 Y，禁止 Z」。可直接作为 code review 检查项。

### 4.1 回车与输入法（最高优先）

- **R1** 当 `e.nativeEvent.isComposing === true` 或 `e.keyCode === 229` 时，**必须**直接 return，**禁止**调用 `preventDefault()`，**禁止**触发发送。中文/日文/韩文输入法选词回车全部走这条。
- **R2** 当非合成态且 `Enter` 且未按 `Shift` 时，**必须**先 `preventDefault()`，**再**判断内容是否为空：空则**什么也不做**（既不发送，也不吞掉换行行为）；非空才发送。
- **R3** 当用户关闭"回车发送"时，**必须** Enter 换行、`Ctrl/Cmd+Enter` 发送；该开关**必须**持久化，并在输入框下方以 `text-caption text-text-tertiary` 常显当前快捷键。
- **R4** 输入框 placeholder **禁止**承载快捷键说明（现在两者挤在一起，窄屏被截断）。

### 4.2 提交防抖与幂等

- **R5** 当 `submitting === true`（从点击到请求 resolve）时，**必须**禁用发送按钮并显示"提交中…"，**禁止**接受第二次提交；输入框设 `readOnly` 而非 `disabled`，保住焦点与光标位置。
- **R6** 幂等键**必须**绑定"一次用户动作"：点击发送时生成新键，仅在该次请求的网络重试内复用。**禁止**用 sessionId 做键，**禁止**写入 localStorage 跨操作复用。
- **R7** 防手抖**必须**靠 in-flight 锁（R5），**禁止**靠长期幂等键——两者混用会产生"第二次生图被吞"这类不可解释行为。
- **R8** 当后端返回"复用已有任务"时，**必须**明确提示"这次提交和 30 秒前的相同，已为你复用"，**禁止**静默清空输入。

### 4.3 内容校验

- **R9** 当内容 `trim()` 后为空，或剔除零宽字符（`\u200B\u200C\u200D\uFEFF\u00A0`）与纯 emoji 后为空时，**必须**禁用发送并在输入框下方给内联提示，**禁止**只在 onClick 里静默 return。
- **R10** 当内容超过 4000 字时，**必须**禁止提交并说明"上限 4000 字，当前 4231 字"，**禁止**静默截断。
- **R11** 当内容被安全策略拦截时，**必须**给改写建议（"试试去掉具体人名/品牌名"），**禁止**只回"内容不合规"。

### 4.4 焦点规则

- **R12** 仅在以下时机**可以**抢焦点：画布框选完成、点"重新生成"、切换会话后恢复草稿、空态示例 chip 点击。
- **R13** 以下时机**禁止**抢焦点：任务轮询刷新、toast 弹出、新消息到达、结果落入安全区。用户正在打字时被夺焦是最伤的操作体验之一。

### 4.5 草稿

- **R14** 输入内容非空时**必须**按会话写入 sessionStorage，页面刷新/误关后恢复；**必须**在发送成功后才清除。

## 5. 生成状态管理与文案

### 5.1 可达状态（本期 6 态 + 1 兼容态）

> `paused` 本期前端**不可达**：上游是同步长请求，没有真挂起能力，"暂停"只改数据库状态、不中断上游，点一次白烧一次上游。本期运行中只保留**「停止生成」**（= cancel，真退款）。`paused` 仅作为历史数据兼容态展示，不提供"继续"入口。

| 状态 | 触发 | 用户可见文案 | 视觉 | 可用操作 |
|------|------|------------|------|---------|
| pending | 点击发送 → 请求返回 | 按钮内「提交中…」 | 按钮 spinner + 置灰 | 全禁（`aria-busy`） |
| queued | 排队（当前后端不可达，需补齐） | 「排队中，前面还有 N 个」 | Clock 静态 + 次要色 | 放弃 |
| running | 生成中 | 「生成中 · 12s，通常 30–90 秒」 | 同尺寸骨架 `animate-pulse` + 计时器 | 停止生成 |
| running 90s | 已等 90s | 「比平时慢一些，可以先去画布看看」 | 追加次要行 | 停止生成 |
| running 180s | 已等 180s | 「仍在生成，超过 5 分钟会自动结束并退回额度」 | 警告色提示条 | 停止生成（主按钮） |
| succeeded（未放） | 结果返回 | 「已完成 · 2 张」 | 缩略图 300ms 淡入 | 放入画布 / 重新生成 / 看大图 / 下载 |
| succeeded（已放） | 已投放 | 「已放入画布」 | 次要色 + success 角标 | 查看 |
| failed | 上游/校验失败 | 「没画成，额度已退回」+ 一句原因 | 红色左描边 + 骨架同位不塌 | 重新生成 |
| timeout | 超过阈值 | 「这次等太久了，已自动停止，额度已退回」 | 同上 | 重新生成 |
| cancelled | 用户停止 | 「已停止，额度已退回」 | 灰化 opacity-70 | 重新生成 |
| paused（兼容） | 历史数据 | 「已停止 · 额度退回中」 | 灰化 + 警告色，**无旋转** | 仅重新生成（**禁止**渲染成无按钮死卡） |

### 5.2 硬规则

- **R15** 生成中**禁止**展示百分比——后端只有 30 一个中间值，任何百分比都是撒谎。用不确定态动画；`prefers-reduced-motion` 下降级为静态 30% 填充（不能停成 0，像坏了）。
- **R16** 生成中骨架**必须**与最终结果同尺寸（`aspect-square rounded-[3px]`），**禁止**让卡片从"一行 spinner"跳变成"大图"，高度跳变会被误读为页面故障。
- **R17** 所有加载态**禁止**全屏遮罩；**禁止**覆盖画布中心 60% 区域；**禁止**加 `backdrop-blur` 盖住已有图片。
- **R18** 运行中卡片**只允许一个破坏性按钮**（停止生成），**禁止**同时出现"暂停"和"放弃"两个语义重叠的按钮。
- **R19** 并发已达上限（2）时**必须**在发送前拦截并提示"同时最多 2 个任务在跑，等一个完成或先停止一个"，**禁止**只靠 429 toast。
- **R20** 任务失败/停止/超时**必须**在卡片上明示"额度已退回"，**禁止**让用户猜是否扣费。
- **R20b** 等待文案**必须**给具体量级（"通常 30–90 秒"），**禁止**使用"马上就好""请稍候"这类无信息量措辞。
- **R20c** 错误编号**本期不做**。若要做，**必须**由后端在唯一异常出口生成并写入日志，客服才能凭码定位；**禁止**前端自行生成——前端造的编号客服 grep 不到，是假承诺。

## 8. 用户不可见内容管控

### 8.0 根因：友好文案这一层从来没有生效过

`frontend/src/i18n/index.ts` 的 `defaultNS: 'common'`，而 `common.json` 只有 `app_name / tagline / action / status / pagination / nav / unit / logout / theme / language / error_boundary`——**没有 `errors` 命名空间**。

于是 `ChatPanel.tsx:97` 的 `te('errors.xxx')`、`errors.ts` 里 `t('errors.xxx')` 全部查不到 key，直接落进两条 raw 兜底：
- `errors.ts:32` `defaultValue: error.message`
- `errors.ts:36` 无 `t` 时 `return error.message`（`ActiveTasksPanel.tsx:26` 调 `toast.fromError(error)` 未传 `t`，必然走这条）

**这意味着"报错文案去技术化"不是漏改了几条文案，而是兜底链一直是断的。** 全站 50+ 处错误提示，一直在显示后端 `envelope.message` 原文——`errors.json` 目前是**死文件**。

**修法有坑，三步必须同时做**（只做前两步中的一步会"以为修完了但界面没变"）：
1. `ERROR_I18N_KEY` 的值**去掉 `errors.` 前缀**（`'errors.upstream_error'` → `'upstream_error'`）；
2. 调用处改为 `t(key, { ns: 'errors', defaultValue: 兜底常量 })`；
3. 单独修 `ActiveTasksPanel.tsx:26`（`toast.fromError(error)` 未传 `t`，是独立缺陷）。

原因：i18next 的 `nsSeparator` 默认是 `':'` 而非 `'.'`，`'errors.upstream_error'` 不会被识别成命名空间，只会被当成 `common` 下的嵌套路径 `errors → upstream_error`，而 `common.json` 没有 `errors` 节点 → 必然 miss → 回落 `error.message`。

**验收前置**：修完后必须先断言 `te('errors.upstream_error')` 返回中文而不是 key 本身，否则改再多文案也白改。
**交叉探针**：把语言切到 English，若报错文案仍是中文 → 该处文案被硬编码，直接判定不合格（这一招能抓出所有"看着像映射、其实是写死"的地方）。
**运行期断言（正则抓不到这个 bug）**：mock 一次 `UPSTREAM_ERROR`，断言 toast 文本**等于** `errors.json` 里 `upstream_error` 的值。静态扫描只能查文案字面量，查不到"文案根本没被取到"。
