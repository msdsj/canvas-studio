## 1. 各成员核心结论

### 🔍 产品评审员（方案评审）
- 核心判断：方案方向正确，但原设计有 4 处会在真实使用中立刻爆掉的问题——未配置时用户无路可走（首启死锁）、公共中转被白嫖、dispatch 仍用用户原话当提示词、技能库只把清单喂给模型等于摆设。
- 关键建议：给「未配置」一条**显式**的本地模板路径（用户点击才走）；`negative` 必须折进提示词（gpt-image 无独立负向参数）；技能要**确定性初筛 + 结构化注入**，不能让模型在 40+ 条里自由选。

### 🛡️ 安全官（OWASP + STRIDE 审计）
- 核心判断：新增的「用户可填 base_url，后端主动发请求」是本期最大攻击面，属典型 SSRF；`extra` 原样并入请求体等于给用户一个任意字段注入点。
- 关键建议：封云元数据地址（169.254.169.254 / fd00:ec2::254 / 100.100.100.200）与平台自身端口，但**必须放行**回环/内网（自托管接本地中转站是合法用法）；响应体加体积上限；`extra` 改白名单；测试接口加限流。

### ✅ QA 与发布（验证）
- 核心判断：功能链路能跑通（含 SSE 阶段事件、澄清不建任务、确认后建任务），但有 3 个阻塞级缺陷：AbortError 不回调 `onClose` 导致切会话后发送键永久禁用；未配置用例查错接口导致「假绿」；幂等键含 `run.id` 等于每次都是新 key。
- 关键建议：把「未生成」的断言直接打到 `generation_tasks` 表；幂等键改成「内容哈希 + 时间桶」。

### 🧩 主理人（实现与收口）
- 核心判断：改造的本质不是加功能，而是**把「先花钱再想」改成「先想清楚再花钱」**；因此所有约束都落在「什么情况下不允许建任务」上。
- 关键建议：`final_prompt` 缺失时宁可失败也不拿原话顶替；澄清卡与思考链路必须能从消息附件还原，否则刷新即失忆。

## 4. 追加修复（2026-10-18 07:56，用户现场）

**现象**：配置 DeepSeek（`deepseek-v4.1-flash`，`https://fast.msdjs.site/v1`）后点「测试连接」，
报 `返回内容为空，检查模型名是否被支持 · 2178ms`；但用户上游日志显示请求 **200 成功**，
且每条 completion tokens 正好 **16**。

**根因**：测试请求里把 `max_tokens` 写死为 16。该模型是思考型（先输出 `reasoning_content`），
16 个 token 全被思考过程吃掉，`content` 为空；而错误文案却把「我们测得太省」说成
「你的模型名不对」——用户配置完全正确。

**修复**（`relay_service.py`）：
1. 测试 `max_tokens` 16 → **256**；
2. `content` 为空时退回读 `reasoning_content`（至少能证明模型在工作）；
3. 按 `finish_reason=length` 区分「被截断」，文案改成「连接正常 · 输出被截断，建议把最大 tokens 调到 512 以上」；
4. 部分中转站不支持 `response_format` → 自动去参重试一次；
5. 正式生成时正文为空不再报「模型名」，而是给出可执行的下一步。

**验证**：新增 2 条回归测试（本地假上游复现「200 + content 空 + finish_reason=length」），
全量 **123 passed / 36 skipped**。
