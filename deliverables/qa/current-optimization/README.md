# 当前需求优化：画布 UI 验证记录

2026-10-20，验证范围：图片浮动操作条、右下导航器、选中图片信息卡、默认结果尺寸。

已验证：

- `npx tsc --noEmit -p tsconfig.app.json` 通过（实际检查前端源文件；仓库的 `npm run typecheck` 只运行根引用配置，单独通过它不能代表源文件检查完整）。
- 5 个修改画布文件的定向 ESLint 通过。
- `npm run build` 通过；仍有既有 GSAP 混合导入与大体积 chunk 提示。
- 所有本次已修改的 Python 文件在检查时均可由 `ast.parse` 解析。

画布调整：

- 操作条使用 26 px 按钮、仅主操作保留文字、70% 底色与磨砂；引用和对比移到「更多」。
- 与图片的默认间距从 18 px 增至 28 px；上下空间不足时尝试图片两侧；空间均不足时放在画布边缘。
- 导航缩略图从 144 × 92 px 缩至 120 × 76 px；选中卡从 232 px 缩为 200 px；导航按钮从 32 px 缩为 28 px。
- 结果默认最长边从 240 px 缩至 200 px，所有落图入口按原图比例计算；修复手动放入正方形拉伸和最小边长造成窄图比例失真。已有聚焦上限为 100%，不会再把 200 px 结果自动放大铺满视口。

视觉验证限制：

- 27180 / 27181 端口没有运行服务。
- 启动 Vite 返回 `listen EPERM: operation not permitted 127.0.0.1:27180`；当前环境不允许提升权限。
- Chrome 自动化仅允许 HTTP / HTTPS，打开本地 file 协议的视觉检查页被安全策略拒绝；没有尝试绕过。
- 因此没有桌面或手机浏览器截图，不能将此记录视为浏览器端到端验证通过。

`canvas-components.html` 是无需后端的独立组件检查页，使用本次真实 React 操作条、导航器、信息卡与已构建生产 CSS，图片为合成无敏感内容。含宽/窄画布切换、图片顶部贴边切换、更多菜单交互，可在正常开发环境启动本地 HTTP 服务后访问。它不发起图像请求、不消耗额度、不包含账号或配置。
