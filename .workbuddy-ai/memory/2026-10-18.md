## 追加修复（同日，用户现场）

**现象**：用户配 DeepSeek（`deepseek-v4.1-flash` / `fast.msdjs.site/v1`）点测试连接，
报「返回内容为空，检查模型名是否被支持」；但上游日志 200 成功、completion tokens 恰好 16。

**根因**：`test_target` 把 `max_tokens` 写死 16，思考型模型把 token 全花在 `reasoning_content`，
正文为空；错误文案却归咎「模型名不支持」。

**修复**（`relay_service.py`）：
1. 测试 max_tokens 16 → 256；
2. `_extract_text` 在 content 为空时退回 `reasoning_content` / anthropic `thinking`；
3. 新增 `_finish_reason`，`length` 时提示「输出被截断，调大 tokens」而不是怪模型名；
4. `chat()` 正文为空时按 finish_reason 给出可执行提示；
5. `json_mode` 遇 400 且错误提到 `response_format` 时自动去参重试一次；
6. 测试接口在 HTTP 200 但无正文时判 **ok=true**（连接/鉴权/模型都通），并说明原因。

**新增回归**：`test_extract_text_falls_back_to_reasoning_content`、
`test_connection_test_does_not_blame_model_when_output_truncated`（本地假上游复现该响应）。
全量 **123 passed / 36 skipped**。

**环境坑**：沙箱内进程无法解析外网 DNS（`getaddrinfo` 失败），且 `nohup`/`run_in_background`
启动的后端会被回收；`launchctl submit` 与 `osascript → Terminal` 均被系统拦。
**结论：改完后端必须由用户自己重启（启动.command 或直接 uvicorn），不要代管常驻进程。**

## 全局动效系统（10:30，GSAP 官方插件）

**用户要求**：一套全局丝滑动画——页面转场、路由跳转、组件切换、元素出现消失、交互反馈（悬停/点击/展开收起），

**依赖**：`gsap@3.15.0`（本地已装）+ 其内置官方插件 `ScrollTrigger` / `SplitText` / `Flip` / `CustomEase`。
统一在 `lib/gsap.ts` 注册（**不能分散注册**：插件没挂上时动画静默失效，dev 正常 build 后可能被 tree-shake）。

**三档节奏 + 两个自定义缓动**（`styles/motion.css`，全站唯一来源）
- `--motion-fast 160ms` 微交互 / `--motion-base 240ms` 局部结构 / `--motion-slow 420ms` 页面级
- `CustomEase 'csPaper'`（M0,0 C0.22,0.61 0.36,1 1,1）日常位移；`'csSnap'` 标签滑块；`'csDrop'` 落地
- 工具类：`.cs-route-enter` `.cs-in` `.cs-in-right` `.cs-pop` `.cs-collapse`（grid-rows 0fr↔1fr）
  `.cs-press` `.cs-hover-lift` `.cs-zoom` `.cs-skeleton` `.cs-bubble-in-left/right`

**落地位置**
- 路由转场：`__root.tsx` 用 `useRouteTransition(viewRef, pathname)`（key 用 pathname，
  查询参数变化不重播）+ `RouteProgress` 顶部 2px 进度条（scaleX，不走 width）
- 弹层：`motion.css` 用属性选择器统一覆盖 Radix 的 `data-state`，popover/menu/select/tooltip/dialog 全覆盖
- 主题切换：`withThemeFade()` 给 `<html>` 临时挂 `.cs-theme-fade`（320ms 后自动摘），不常驻
- 首页：`useSplitReveal`（SplitText 逐字升起，**结束后必须 revert**）+ `useSpotlight` 光标光斑
- 侧栏：`useListReveal` + 标签切换 90ms 淡出再换内容（`displayTab`）
- 按钮：`Button` 变体加 `hover:-translate-y-px active:scale-[0.985]`，transition 覆盖 transform

**踩坑（重点）**
1. **CSS keyframes 的 transform 会覆盖 Tailwind 的 `-translate-x-1/2`**：dialog 用 `translate` 属性居中，
   所以 `cs-dialog-in/out` 只能动 `opacity/scale/translate` 属性，**绝不能写 transform**，否则弹窗飞出屏幕。
2. `SplitText` 的 `mask: 'chars'` 不能在动画后保留，否则行高被切断（g/y 下伸部分被裁）。
3. `useLayoutEffect` 而非 `useEffect` 写初始态，否则会先闪一下完整内容再播动画。
4. 降级链：`prefers-reduced-motion` → `.cs-reduced`；`deviceMemory≤4 / cores≤4 / saveData` → `.cs-lite`
   关掉持续氛围动画（`installMotionProfile()` 在 App 挂载时跑一次）。

**验收**：tsc 0 error / eslint 0 error / build 通过；真实 CDP 验证
①`cs-pop-out 0.2s` 菜单动画生效 ②`cs-theme-fade` 60ms 内挂上、450ms 后摘除 ③按钮 transitionProperty 含 transform

**现象**：已读过的任务反复弹「已完成 / 1 张」。

**根因（三处叠加）**
1. `ChatPanel` 的去重集合 `knownSucceededRef` 是 **useRef**：路由进出、切会话、HMR 都会重新挂载，
   集合清空 → 整批历史任务重新算作"新到达"。
2. 「首次进会话只做基线」的保护有漏洞：进页面时任务还是 running（不在 succeeded 列表里），
   基线里就没有它的 id，等它变 succeeded 就被当成新结果弹一次——而这个任务用户早就看过了。
3. `ResumeGuard` 另存一套 `cs.notifiedTasks`（布尔），与 ChatPanel 各弹各的、互不同步。

**修复**
- `lib/task-persistence.ts` 新增唯一真源 `cs.notifiedResults`：`{ 任务id: 已提示过的结果张数 }`。
  存**张数**而非布尔——重试后从 1 张变 2 张是真·新结果，应再提示；张数没变绝不重复。
- `ChatPanel`：改为读这份持久记录；并用 `watchersRef`（本次停留期间见过 running 的任务）
  区分"刚跑完"与"历史结果"，历史结果只记账不打扰。
- `ResumeGuard`：删掉自己那套布尔记录，改用同一份张数记录（两边不再各弹一次）。

**视觉重做**（`styles/toast.css` + `components/ui/toast.tsx`）
- 纸卡片语言：圆角 14px、1px 细边、双层软影；左侧 3px 语义竖条（成功=青柠/错误=红/警告=琥珀/信息=墨）
- 图标改 26px 圆形色底，不再整卡染色（避免和品牌青柠打架）
- 关闭按钮从「卡片外沿左上」挪进卡片内右上角，平时透明、悬停才显形
- 堆叠收缩态压成 6px 窄边（sonner 默认保留整卡高度 → 看起来像一叠空白壳）
- 宽度走 sonner 的 `--width`（332px），移动端 `calc(100vw - 24px)`；字体接到站点无衬线族

**踩坑（重要）**
- ⚠️ sonner 内置规则是 `[data-sonner-toast][data-styled='true']`，且它的样式表后加载。
  只写 `.cs-toast` 会被压回去（改了 CSS 但界面毫无变化）。必须用双属性前缀 + `!important`。
- ⚠️ 宽度不能用 Toaster 的 `width` prop（2.x 与 CSS `--width` 冲突），直接设 CSS 变量。
- ⚠️ hover 不能写 `transform`：sonner 用 transform 做堆叠位移，覆盖会让卡片错位。

## Excalidraw 国际化修复（09:45）

## 画布「点击=引用 / 框选=就地编辑」边界修复（20:55）

**用户反馈**：框选区域后编辑功能跑到了侧边栏对话里；点图片应把图插进全局输入框；
框选后要在框选处的气泡里直接写、直接标注，两条路径不能互相干扰。

**根因（三处叠加，缺一不可）**
1. `WorkspaceView.handleSelectionChange` 只判 `if (!target)`，**不看 `regions.length`**：
   只要编辑层开着（点过图就有 target），哪怕一个区域都没框，也会把一个空 `selection`
   上抛给 `ChatPanel`。
2. `ChatPanel` 的 `hasSelection = (selection?.regions?.length ?? 0) > 0` 太宽，
   且 `send()` 里 `if (hadSelection) → submitSelection()` 抢在 `submitCompose` 前面——
   于是用户在对话里打的普通描述被当成「区域编辑」送进 `/chat/analyze`。
   这就是「编辑功能转移到了侧边栏对话里」的直接原因。
3. 点击判定里另有一道「有选区就整笔跳过」的重复条件，会吞掉「编辑层已开、又点了另一张图」
   这类本该走引用路径的点击。

**修法**
- `handleSelectionChange`：`!target || regions.length === 0` → `setSelectionCtx(null)`。
  **空选区 = 没有选区 = 对话里那句话就是普通生图需求。**
- `hasSelection` 收紧为「有区域 **且** 每个区域都写了改法」：只框没写字不算编辑需求。
- 点击判定只认「位移 ≤ 5px 且时长 ≤ CLICK_MAX_MS」，并新增
  `closest('[data-edit-layer-ui]')` 排除点在自己 UI（编号徽章、气泡按钮）上的点击。
  **判定依据统一成"这一笔是不是拖拽"，不再看是否已有选区。**
- 编辑层 UI 打标 `data-edit-layer-ui`；气泡「去创作」的 `text-white` → `text-text-inverse`。

**回归资产**：`e2e/canvas_interaction.assert.mjs`（纯静态断言，不需要起服务，8 条全绿）。
链路判定改动用它跑一遍，比重开浏览器快得多。

**环境坑**：Vite 只监听 `[::1]:27180`，浏览器访问 `127.0.0.1:27180` 会 `ERR_CONNECTION_REFUSED`；
本机还有系统代理，`curl`/Chrome 都得走 `localhost` + `--no-proxy-server` / `--noproxy '*'`。
