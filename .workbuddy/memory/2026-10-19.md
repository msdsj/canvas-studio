## 21:12 重启 + 修复 i18n 全面失效（严重）

### 现象
重启后页面**整片露出原始 key**（`panel_title`、`save.saved`、`toolbar.add_image`、`error_boundary.title`），并连续触发 error boundary：
```
TypeError: suggestions.map is not a function   (HomeComposer)
TypeError: rows.map is not a function          (StyleMarquee)
TypeError: items.map is not a function         (InspirationGallery)
```

### 根因（★ 关键，别再踩）
`frontend/src/i18n/index.ts` 里这两个选项**互相打架**：

```ts
supportedLngs: ['zh-CN', 'en'],
nonExplicitSupportedLngs: true,   // ← 元凶
```

`nonExplicitSupportedLngs` 会把 `zh-CN` 拆成**基码 `zh`** 去匹配 supportedLngs；而资源是按 `zh-CN` 存的 → 查不到任何 bundle → **所有 `t()` 原样返回 key**。

后果连锁：
1. `t(key, { returnObjects: true })` 返回的是**字符串**而非数组
2. 组件里 `.map()` 直接 `TypeError` → 整个页面被 error boundary 接住
3. 连 error boundary 自己的文案也显示成 key（因为翻译全挂）

### 定位过程（可复用）
1. CDP 抓 console.error → 拿到具体组件和行号
2. 页面出现**原始 key** 时，别急着改组件，先怀疑 i18n 整体失效
3. 纯 Node 复现（不依赖浏览器/Vite）：用 `i18next/dist/esm/i18next.js` + 直接读 locale JSON，跑 `init()` + `t()`
4. **逐项二分选项**：单项都通过，叠加才失败 → 锁定冲突组合
   - `supportedLngs + nonExplicitSupportedLngs` = ✗
   - `supportedLngs` 单独 = ✓，`nonExplicitSupportedLngs + load:currentOnly` = ✓

### 修复
1. **删除 `nonExplicitSupportedLngs: true`**（根治）。语言变体回落由 i18next 自带 best-match 完成，实测：
   `zh-CN→zh-CN` / `zh-TW→zh-CN` / `en→en` / `en-US→en` / `fr-FR→zh-CN(fallback)` 全部正确。
2. 新增 `asList<T>()` 工具并导出（`@/i18n`），把 4 处 `t(key,{returnObjects:true}) as string[]` 全部替换：
   - `components/home/HomeComposer.tsx`（placeholders / suggestions）
   - `components/home/StyleMarquee.tsx`（rows，`string[][]`）
   - `components/home/StoryDemos.tsx`（parts）
   - `components/home/ShowcaseStory.tsx`（bullets）
   作用：即使将来某个语言缺键，也只会渲染空列表，不会打穿整页。
3. 清理：`InspirationGallery.tsx` 的 `items.map` 崩溃随根因修复自动消失。

- 工作台：Toolbar 文案恢复正常（"添加图片到画布 / 上传图片 / 图层"），无异常
